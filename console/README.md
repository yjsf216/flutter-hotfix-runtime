# 独立热更新管理后台（Android 本机 MVP）

不需要 Jenkins、数据库、云账号或前端开发环境。自带 Vue 3 预构建页面，
以简洁的左侧菜单、顶部导航、表格和确认弹窗组织操作。
它复用现有编译器、签名工具和分发协议，不扩大 Dart 热更新的支持范围。

## 首次使用

1. 按 [首次接入](../GETTING_STARTED.md)准备固定工具链，在 App Git 根目录运行
   `hotfix init`，审查、测试并提交接入改动。当前工具链仍需自行准备，后台不会自动下载 Engine。
2. 仍在 App 根目录运行：

   ```sh
   sh /path/to/flutter-hotfix-runtime/tool/hotfix console --with-delivery
   ```

   默认管理页面是 `http://127.0.0.1:8765`。`--with-delivery` 同时启动配置中
   显式允许的开发 HTTP 分发服务；如果该端口已有服务，请去掉此参数。
   HTTPS 分发服务按 [部署说明](../delivery/README.md)单独运行，启动后台前通过
   `HOTFIX_PUBLISH_TOKEN` 环境变量安全注入发布凭据，不要写进 Git、命令行参数或浏览器。
3. 启动提示会给出 `.hotfix/console/access-token` 文件路径。自行读取其中的令牌，
   填入登录框。它与发布令牌不同，仅用于本机管理 API；浏览器不保存到本地存储或 URL。

Python 3.10+、Git、已完成初始化的 App 和对应工具链是必需的。运行预构建页面不需要 Node。
可加 `--project /absolute/app/path` 指定工程，加 `--port 8767` 更改管理端口。
后台没有 `--host 0.0.0.0` 选项；第一版不是公网、多用户管理平台。

## 日常操作

### 发布完整 App

在原工程正常开发、测试、提交，打开“基础版本”，选择发行提交，点击“构建基础版本”。
后台生成并验证 APK，保存完整基线。下载 APK 后自行通过原有渠道分发。
它不会自动安装设备、推送代码或发布安装包。

基线不是任意 Git 提交。只有后台成功构建并归档的版本才能在列表中选择。
本版暂不导入原命令行工作目录的历史基线；原 CLI 的归档和使用方式仍保留。
第一次采用后台时需构建新的发行基线，不会修改已安装 App 或让旧 APK 自动获得更新能力。

### 修复已发布版本

1. 在对应版本的修复分支正常改代码、测试并提交，App 版本号保持与基线相同。
2. 打开“补丁构建”，选择基础版本和完整的修复提交，点击“生成补丁”。
3. 查看任务日志。编译器不支持的修改明确失败，不进入可发布列表。
4. 在测试环境验收补丁和实际业务。“生成成功”不是业务正确性的保证。
5. 打开“发布管理”，核对版本、App、补丁和目标地址，点击“发布”并确认。
6. 用户 App 检查下载后，在下一次冷启动生效；在“运行结果”选择基线查看报告事件。

页面从原本机仓库展示最近 100 条可达提交。新代码请先提交，尚未拉到本机的远程提交
需要自行拉取；“同步提交”只更新专用构建副本，不自动访问 Git 托管平台。
后台最终固定完整 SHA，不把可变的分支名作为任务输入。

### 撤回与重试

“撤回”使用同一签名工具产生新的撤回策略，再上传到冻结的分发地址。
它不是删除服务器文件，也不是立即切换正在运行的 App。客户端下次检查后按现有回退策略处理。
撤回不能取消；后续修复要生成新补丁。

网络错误可能发生在服务器已接收之后，所以页面会保守显示“发布结果待确认”。
重试发布会重传原签名包；重试撤回也会复用已生成的原撤回包，不重新签署不同内容。
不要通过手动改后台 JSON 把“待确认”改成“未发布”。

运行结果展示去重后的**事件数**，不是独立用户数或用户成功率。当前没有真实用户数统计。

## 工作目录与执行器

后台在 App 的同级目录创建固定的 `.hotfix-console-<工程路径摘要>` 专用 Git 副本。
选择提交时只切换这个副本，不切换原工程，不 reset/stash 原工程，也不复制未提交源码。
同级目录用于保持已有相对路径依赖的目录深度；这不是容器沙箱。

状态、管理令牌和任务日志位于原工程 `.hotfix/console/`；发行归档与补丁位于专用副本的
`.hotfix/releases/`、`.hotfix/patches/`。**两处都需备份**，不能只备份 Git。
签名密钥沿用初始化配置中的绝对路径，不生成替代密钥。
复制已存在且未被 Git 跟踪的 `android/local.properties` 和 `android/key.properties`。
选定提交未跟踪 `pubspec.lock` 时，会复用原工程现有锁文件，避免新副本自行升级依赖；
选定提交已跟踪的锁文件不会被覆盖。Android 任务解析依赖时生成的已跟踪桌面插件注册文件
不参与 Android 构建：后台保存其生成内容后恢复原字节，其他源码变化仍会被构建门禁拒绝。
其他忽略文件不自动复制。签名 keystore 路径需指向构建副本也能访问的文件，推荐绝对路径。
涉及其他未跟踪构建输入的项目需要自行配置，任务失败时检查日志。

基线、源码提交、版本、工具指纹、签名、公钥、APK 内容验证全部继续由现有 CLI 执行。
工具源码改变时，不会绕过冻结工具指纹检查；需恢复匹配版本或构建新基线。
后台也不会重编译已发布补丁，只发布选定的不可变产物。

内置执行器一次只运行一个任务，构建通过独立子进程执行；任务状态持久化。
后台重启后把未完成任务标记为中断，不自动恢复或发布；已完成的归档仍保留。
Ctrl+C 会停止本后台启动的构建进程组，以及 `--with-delivery` 启动的服务，不停止外部服务。
日志最多保留前 8 MiB，页面显示最近 256 KiB；任务历史限 1000 条，达到后需备份迁移。

## 管理 API

仅监听 `127.0.0.1`。所有 `/api/` 请求使用管理令牌：
`Authorization: Bearer <access-token>`。默认不允许 CORS，检查 Host 和 Origin。
POST 必须是 `Content-Type: application/json`，正文上限 4 KiB。

| 接口 | 作用 |
|---|---|
| `GET /api/state` | 工程、提交列表、基线、补丁、任务和工具路径检查 |
| `POST /api/tasks` | 提交串行任务，成功返回 202 和任务 ID |
| `GET /api/log/<taskId>` | 读取该任务日志尾部 |
| `GET /api/apk/<baselineRecordId>` | 哈希校验后下载归档 APK |
| `GET /api/stats/<baselineRecordId>` | 使用服务端发布凭据查询并筛选对应基线的报告事件 |

任务 JSON：

```json
{"action":"build","commit":"完整提交SHA"}
{"action":"patch","baseline":"基线记录ID","commit":"完整提交SHA"}
{"action":"publish","patch":"补丁记录ID","confirmed":true}
{"action":"withdraw","patch":"补丁记录ID","confirmed":true}
{"action":"refresh"}
```

这里的记录 ID 来自 `/api/state`，不是 App 使用的 SHA256 baselineId。
管理 API 与 [App 分发 API](../delivery/README.md)是两套接口。
此版本支持任意已接入的 Android 工程，但每个实例只管理一个工程；多个工程使用不同端口。
Jenkins 不参与默认路径，也没有作为必装依赖。

## 安全边界

- 只运行自己信任的仓库和提交。Gradle、pub 及构建脚本拥有当前用户权限；专用目录不是沙箱。
- API 鉴权不能防止恶意本机用户篡改文件，存储目录必须由操作人控制。
- 私钥和发布令牌不返回浏览器。构建子进程不继承 `HOTFIX_PUBLISH_TOKEN`；发布凭据只传给发布进程。
- 不要把本机后台经反向代理直接暴露公网。公网、多用户场景需要 HTTPS、权限隔离、审计、
  凭据治理与隔离执行环境；这些不在本机 MVP 范围内。
- 日志对已知管理/发布令牌做遮蔽，但无法保证业务项目的构建脚本不打印其他业务凭据。
  项目自身应避免把密码、私钥等写入构建日志。

## 开发与验证

```sh
python3 -B console/server_check.py
python3 -B tool/app_cli_check.py
python3 -B tool/android_release_check.py
cd console/web
npm ci
npm run build
```

前端依赖通过锁文件固定，产物在 `console/static/`，随源码分发。
只有修改前端的人需要 Node（匹配 Vite 的 Node 要求）；普通使用者不需要 npm。
第三方许可证见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

  再向隔离的本机分发服务发布和签名撤回。归档 APK 经鉴权下载，内容哈希一致。
- 浏览器验证登录、Git 提交选择、网页发起补丁构建、日志、发布状态、撤回确认与取消、

当前不接 iOS/OHOS，不包含 Jenkins 适配、远程多执行器、自动灰度策略、审批流或基线导入。

## 局域网开发测试

按照[Wi-Fi 测试接入](../GETTING_STARTED.md#使用-wi-fi-局域网无需-usb-转发)显式开启
`--dev-lan`，或手动适配已有配置及 Android 精确网络白名单，重新构建基础 APK。
`console --with-delivery` 将分发服务绑定到配置里的私有 IPv4，管理页面仍只监听本机。
发布、撤回和统计均使用冻结基线里的局域网测试地址，不允许网页任意替换目标。

2026-10-10 的有限传输验收：同一 Wi-Fi 上的真实 Android 手机直接通过电脑的私有 IPv4
获取了签名清单和 DBC3 补丁字节，清单与原文件一致，补丁哈希与签名清单及原文件一致。
没有新增 USB reverse，没有安装或清除手机 App；这证明了局域网分发传输，
不构成新局域网 APK 的冷启动生效验收。

2026-10-13 已进一步完成独立业务 Android 工程的真实局域网闭环：后台构建发行基线、
两处方法补丁编译签名、Wi-Fi 下载、冷启动加载并健康上报、签名撤回、再次冷启动恢复基线。
首页真机文案与恢复结果已确认；另一处设置页修改通过 Widget 测试，未完成真机页面视觉确认。
未使用 USB reverse，安装沿用原签名并保留数据。新副本构建暴露的未跟踪依赖锁文件及
桌面自动注册文件问题已修复，相关后台测试现为 12 项通过。
