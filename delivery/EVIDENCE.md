# Online delivery: Android + iOS device evidence

On 2026-09-10 both authorized devices completed the minimum online loop using
the actual custom Flutter Release/AOT/DDM Engine and shared signed loader.
No patch file was manually placed in either app's inbox for these online tests.
Apps were updated without uninstalling or clearing their data.

| Stage | Android `ANDROID_DEVICE_SERIAL` | authorized iPhone (iOS 15.8.7) |
|---|---|---|
| Signed bytecode uploaded by CLI | HTTP 201 | HTTP 201 |
| First startup | Baseline page healthy | Baseline page healthy |
| App checks and downloads | `downloaded` report received | `downloaded` report received |
| First-run store | Selected `delivery-p1`, LKG null | Selected `delivery-p1`, LKG null |
| Next cold startup | Patched page healthy | Patched page healthy |
| Second-run store | Selected/LKG `delivery-p1`, pending null | Selected/LKG `delivery-p1`, pending null |
| Server observation | `patch_healthy` received | `patch_healthy` received |

The shared fixture asserts actual mounted Text and first-frame rasterization
before health is reported. Native state and patch digests were independently
fetched and checked. The first process did not activate its download.

Artifacts and machine-readable checks: `work/delivery-device.CzYuVJ/`:

- `delivery-evidence.json`: checked state and event sequence per platform.
- `server/reports.jsonl`: server-received baseline/download/patch health events.
- `android-first.log`, `android-second.log`, `android-*-state.json`.
- `ios-first-state.json/Documents/hotfix/store/state.json` and corresponding
  `ios-second-state.json/...` (ios-deploy preserves container subdirectories).
- `android-delivery.apk`, `ios-build/Build/Products/Release-iphoneos/HotfixRuntime.app`.
- `android/`, `ios/`: frozen releases, original snapshots and signed-patch inputs.
- `cli-patch.log`: separate patch-only CLI generated byte-identical Android DBC3
  without rebuilding the frozen release.
- `host-regression.log`: the real host AOT Engine regression output.

Client identity now embeds app ID and platform as well as the frozen baseline.
Both apps used the same test public key, but their manifests bind different
app/platform/baseline identities. Test keys and publishing token remain ignored
local artifacts; the private key and administrative token never enter an app.

The service used HTTP only for explicit development: Android via device-specific
USB reverse forwarding, iOS via the development Mac's LAN address. HTTPS
production deployment, App Store review, persistent telemetry retries, rollout,
withdrawal and arbitrary-project integration are not claimed by this test.
